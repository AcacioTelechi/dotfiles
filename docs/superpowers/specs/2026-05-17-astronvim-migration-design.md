# AstroNvim Migration — Design

Date: 2026-05-17
Branch: `astronvim-migration`
Status: Approved (design); pending spec review

## Goal

Replace the hand-rolled `nvim/.config/nvim/init.lua` configuration with the
AstroNvim **v6+** distribution, using AstroNvim's defaults for tooling, while
re-applying the user's personal preferences (keymaps, vim options, colorscheme,
one personal plugin) as AstroNvim user overrides.

## Decisions (locked)

- **Migration intent:** Full AstroNvim template, personal preferences re-applied
  on top.
- **Tooling:** Use AstroNvim defaults (completion, LSP, formatting, statusline,
  file tree, which-key). The session-built stack is discarded as redundant.
- **Language support:** Add AstroCommunity language packs for Lua, Python,
  JS/TS, JSON (each bundles LSP + formatter + linter + treesitter).
- **Strategy:** Approach A — work on branch `astronvim-migration`, validate,
  then merge to `main`. Old config remains recoverable via git.

## Repository / stow context

- Stow package: `nvim/.config/nvim/`. `~/.config/nvim` is already a symlink
  into the repo, so new template files appear live with no re-stow.
- All migration work happens on branch `astronvim-migration`; merge to `main`
  only after validation.

## Target structure (AstroNvim v6 template)

Replace the contents of `nvim/.config/nvim/` with:

```
init.lua
.luarc.json
.neoconf.json
.stylua.toml
selene.toml
lua/lazy_setup.lua
lua/community.lua
lua/polish.lua
lua/plugins/astrocore.lua
lua/plugins/astrolsp.lua
lua/plugins/astroui.lua
lua/plugins/mason.lua
lua/plugins/none-ls.lua
lua/plugins/treesitter.lua
lua/plugins/user.lua
```

The old single `init.lua` is deleted (replaced by the template's `init.lua`).
`lazy-lock.json` is regenerated by AstroNvim on first sync.

## Preference mapping

### `lua/plugins/astrocore.lua` → `opts.options.opt`

Only non-default settings (AstroNvim already sets relativenumber, number,
signcolumn, etc.):

- `colorcolumn = "100"`
- `scrolloff = 10`, `sidescrolloff = 10`
- `tabstop = 2`, `shiftwidth = 2`, `softtabstop = 2`, `expandtab = true`
- `conceallevel = 2`
- `timeoutlen = 500`
- `undofile = true`
- `undodir` = `~/.vim/undodir` (expanded absolute path)

### `lua/plugins/astrocore.lua` → `opts.mappings`

Modes `n` and `v` as appropriate, each with a `desc` for which-key:

| Key | Mode | Action | desc |
|-----|------|--------|------|
| `<A-j>` / `<A-k>` | n, v | Move line/selection down/up | Move line/selection |
| `<A-h>` / `<A-l>` | n, v | Indent left/right (reselect in v) | Indent |
| `<S-A-j>` / `<S-A-k>` | n, v | Duplicate line/selection down/up | Duplicate |
| `<` / `>` | v | Indent and reselect | Indent and reselect |
| `<F12>` | n | LSP go to definition | Goto definition |
| `<S-F12>` | n | LSP find references | Find references |

AstroNvim's own `gd` / `gr` are kept; `<F12>` / `<S-F12>` are additive.

### `lua/polish.lua`

- Create `~/.vim/undodir` if it does not exist (mkdir -p equivalent), matching
  the original config's behavior.

## Colorscheme + language packs

### `lua/community.lua`

```lua
return {
  "AstroNvim/astrocommunity",
  { import = "astrocommunity.colorscheme.catppuccin-nvim" },
  { import = "astrocommunity.pack.lua" },
  { import = "astrocommunity.pack.python" },
  { import = "astrocommunity.pack.typescript" },
  { import = "astrocommunity.pack.json" },
}
```

Pack slugs: `lua`, `python`, `typescript` (TS/JS via ts_ls + prettier +
eslint), `json`. These exact slugs are confirmed against the live
astrocommunity repository as the first implementation step before any commit;
if a slug differs upstream, the corrected slug is used (this is verification,
not an open design question).

### `lua/plugins/astroui.lua`

- `opts.colorscheme = "catppuccin"`

## `lua/plugins/user.lua`

- Add `christoomey/vim-tmux-navigator` with `<C-h/j/k/l>` /
  `<C-\\>` mappings (the user's tmux integration; not covered by AstroNvim
  defaults).

## Discarded as redundant

Replaced by AstroNvim defaults or language packs:

- Hand-rolled lazy.nvim bootstrap
- `blink.cmp` (→ AstroNvim default completion)
- `efm` + `efmls-configs-nvim` + selene/black/flake8/prettierd/eslint_d
  (→ language pack formatters/linters)
- `lualine.nvim` (→ AstroNvim heirline statusline)
- Custom telescope setup + LSP picker keymaps (→ AstroNvim telescope + default
  LSP mappings)
- Custom nvim-treesitter config + `branch = "master"` pin (→ AstroNvim-managed
  treesitter; the `except*` query warning becomes moot)
- Custom `gitsigns.nvim` config (→ AstroNvim default gitsigns)
- `nvim-tree.lua` (→ AstroNvim's neo-tree; toggle becomes `<Leader>e`)
- Custom `which-key.nvim` config (→ AstroNvim default which-key)

## Known behavior changes (accepted)

- File tree: `nvim-tree` → **neo-tree**; toggle key changes to `<Leader>e`.
- Statusline: custom/lualine → **heirline** (AstroNvim look).
- Completion engine: blink → AstroNvim default.
- The treesitter `except*` Python warning disappears (config no longer pins
  the frozen `master` branch).

## Validation steps

1. Headless parse/health check of the new config (no Lua errors).
2. Confirm catppuccin colorscheme loads.
3. Confirm language packs install servers (Lua, Python, JS/TS, JSON) via Mason.
4. Confirm preserved keymaps resolve and show which-key descriptions.
5. Confirm `~/.vim/undodir` is created and `undofile` works.
6. Confirm `vim-tmux-navigator` keys work.
7. Merge `astronvim-migration` → `main`, push.

## Out of scope

- Reproducing AstroNvim defaults the user did not ask to keep.
- Tuning AstroNvim beyond the listed preferences.
- The deferred nvim-treesitter `main`-branch migration discussion (moot under
  AstroNvim).
